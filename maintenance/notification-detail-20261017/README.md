## Поведение

Карточка списка открывает существующий маршрут Notifications с параметром notificationId. В URL только идентификатор; текст, суммы, имена и объект уведомления туда не передаются. Подробности заново сопоставляются с текущими данными авторизованного пользователя. Browser Back и кнопка «Назад» возвращают в список; при входе по прямой ссылке список заменяет detail. Существующая строка сохраняет scroll/focus после возврата. Для уже зарегистрированного Notifications добавлена явная path-привязка в1033: прежний сериализованный адрес сохранялся при клике, но до этого не распознавался после reload.

Вёрстка принята из detail-r1: тип/время, заголовок, полный доступный текст уведомления, связанный объект и одна основная кнопка. Murs/Onest, круглая Back52px и светлая основная52px сохранены; текст прокручивается независимо от нижней кнопки. Награды используют нейтральный placeholder, люди — существующий avatarUrl или инициал. Логотипы и фотографии не создаются, стрики не включаются.

Используются реальные текущие поля. Вымышленные люди, даты, номера, суммы, сроки и ответы из fixture концепта в feed не переносятся. Из уже загруженного билета добавляются orderId, название/время/место события, билет и количество; из существующей строки сервера — разрешённые event/payload metadata. Нет новых типов запросов, endpoint, RPC, прав или ролей. Полный ответ поддержки остаётся на существующем экране обращения: API уведомления его не содержит, поэтому в detail не подставляется пример ответа. Сумма возврата показывается только из целого неотрицательного payload.total в копейках; статус денег/допуска остаётся в заказе, срок зачисления не придумывается.

Основная кнопка выбирается по существующим ID: ticket/refund→Ticket(orderId), follow→UserProfile(userId), support/support_due→SupportThread(threadId; у staff as=support), badge→Profile tab=ach, событие→EventDetail(eventId), мера/поддержка без threadId→Support. Сводка претензии не изображается готовой отдельной функцией: при наличии eventId кнопка честно называется «Открыть событие». При отсутствии связанного объекта — пояснение и возврат в список.

Поток данных сохранил SELECT, RLS/blocks, источники achievements/orders и realtime filter. Дополнены состояния pending/error/retry для чтения серверных уведомлений, generation/owner guard отклоняет поздние ответы старого пользователя. Loading также учитывает существующие hooks tickets/achievements. Их внутренние error contracts не переделаны; server error проверен отдельно. Детали не добавляют mark-read RPC: прежний read/seen выполняется на списке. Другие каналы/native/backend/рассылки/PAY/Auth/ONB и dirty site/main/app не меняются.
